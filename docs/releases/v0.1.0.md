# cnmv-iic v0.1.0

First public release of `cnmv-iic`: open, reproducible, traceable
infrastructure to reconstruct the registry, time series, portfolios,
exposures, and historical lifecycle of Spanish collective investment
schemes (IIC) from official CNMV evidence.

Released on commit `83935e3` — **bit-identical to the validated
`v0.1.0-rc1`**; no line changed between release candidate and final.

## What ships

- `cnmv-iic` CLI + stable Python API (`cnmv_iic.api.open_dataset()`).
- `sync` — reproducible local build from CNMV sources.
- `verify` — offline fingerprint re-derivation over stored artifacts.
- Immutable content-addressed source-artifact ledger (SHA-256).
- Canonical Parquet dataset + DuckDB query layer.
- G9 lifecycle read model: source-assertion ledger, preregistered
  7-rule adjudication engine, derived `ABSORBED_BY` lineage edges.

## No CNMV data redistribution

This release ships code, manifests, fingerprints, and synthetic
fixtures only. Raw CNMV bytes are never redistributed
(`docs/releases/distribution-policy.md`). The complete normalized
dataset remains `REQUIRES_LEGAL_REVIEW` and is not published.

## Demonstrated reproducibility

Verified during release hardening, from clean environments and fresh
directories (not from a pre-existing dataset):

- `2012-03` and `2025-12` re-downloaded from CNMV produced
  **byte-identical source artifacts** (same SHA-256) and **identical
  canonical fingerprints** across all six families (dataset, registry,
  daily, quarterly, patrimony, derivatives).
- `verify` on the fresh dataset: `SAME_SOURCE_SET_SAME_DATASET`.

## Source-set identity vs local derivation

`verify` reports a `source_set_fingerprint` (hash of sorted
`(period, source_family, artifact_sha256)` triples) and a verdict:

- `SAME_SOURCE_SET_SAME_DATASET`
- `SOURCE_REVISION_DETECTED` — CNMV republished a period with different
  bytes; a different result is then a source revision, not a local
  reproducibility failure
- `LOCAL_DERIVATION_MISMATCH`
- `MISSING_SOURCE_ARTIFACT`

## Operational budget — full rebuild `sync --from 2012-01`

Measured on the reference build:

- ~16 h of polite CNMV downloads (~4,400 requests)
- ~1.5 GB raw source artifacts
- ~570 MB resulting Parquet dataset
- ~0.6 GB peak RAM per period update

## Frozen contracts

- `dataset_schema_version=1`, `canonical_model_version=0.1.0`,
  `parser_version=0.1.0`
- `lifecycle_engine_version=g9e-v1` — frozen preregistered rules; any
  rule change is a new engine version (`g9e-v2`), never a silent edit.
- Breaking changes to any layer require a version bump or explicit
  migration — never semantic drift under the same version string.

## Known operational caveat

On Windows, a transient filesystem lock on a just-written source
artifact once caused `verify` to report `LOCAL_DERIVATION_MISMATCH`
(re-parse read failure). This is fail-closed behavior working as
designed — it reported rather than silently passing — and reruns were
stable. Not a semantic defect; if seen, re-run `verify`.

## Maintenance policy

- `0.1.x` — bug fixes, docs, packaging, operational hardening only; no
  semantic reinterpretation.
- `0.2.0+` — new source/data capabilities.
- `dataset_schema_version > 1` — only for incompatible dataset contract.
- `g9e-v2` — only with new evidence/rules and a fresh validation
  protocol.
